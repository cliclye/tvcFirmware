From code to board.

A USB-C connector provides transport. The firmware still needs the exact board wiring.

What is ready

Profile editing, simulation using the C controller, CRC-protected settings, serial transport, and a USB DFU utility. The core is host tested. The available MCU image is a blank bring-up image and does not operate TVC.

What is needed for physical TVC

  1. EasyTVC v0.1 schematic or verified pin map: sensor bus pins and chip selects, servo timer pins, clock, USB, and arm input.
  2. Servo model, measured endpoints, linkage direction, gimbal geometry, and the board-to-rocket orientation.
  3. Board drivers for sensors, USB CDC, PWM, watchdog, and atomic settings storage; then powered bench validation.

USB-C upload workflow

  1. Use a data-capable USB-C cable. Keep motors, ignition, and recovery charges disconnected during bring-up.
  2. Enter the STM32 ROM bootloader using the board’s BOOT/RST controls. Confirm the exact sequence with the board documentation.
  3. List the DFU device with python3 scripts/dfu.py list.
  4. Inspect an appropriate image with python3 scripts/dfu.py inspect path/to/firmware.bin. Confirm the board, image purpose, address, and hash.
  5. The explicit flash command downloads and reads back the bytes for verification. See docs/usb-and-studio.md for the command. Studio does not flash from a browser.

Weather and reliability

Increasing PID gains can produce oscillation or saturate a servo. Wind tolerance depends on available thrust and torque, inertia, aerodynamics, servo speed, structural limits, and the actual flight conditions. Simulation is a tool for exploring those relationships; measured bench and flight evidence establishes usable limits.

This workspace does not implement a flight recovery system. Pyro outputs remain disabled. Do not use it as the sole flight or recovery computer.
